# C23b: Session Management UI (Cashier & Admin)

## Traceability
*   **User Stories**:
    *   **US-01**: Open Session (Count Float) - [P1]
    *   **US-02**: Close Session (Blind Count) - [P1]
    *   **US-03**: Cash In / Cash Out - [P1]
*   **Sequence Diagrams**:
    *   `Session Reconciliation (Blind Count)` (from `pos_sequence_diagrams.md`)

## Goal
Implement the UI flows for **Opening**, **Managing** (Cash In/Out), and **Closing** a POS Session.
This includes both the "Cashier Actions" (Modals) and the "Admin Views" (List/Details).

## Proposed Changes

### 1. POS Components (`packages/core/src/modules/pos/components/sessions`)
*   `[NEW] SessionOpenDialog.tsx`: Modal to enter Opening Float.
    *   Input: `openingFloat` (Currency).
    *   Action: Calls `pos.session.open` command.
*   `[NEW] SessionCloseDialog.tsx`: Multi-step Wizard.
    *   Step 1: **Blind Count**. Cashier enters `closingCash`. Hides expected amount.
    *   Step 2: **Variance Check**. Shows `difference` = `closing - expected`.
    *   Step 3: **Confirm**. Calls `pos.session.close`.
*   `[NEW] CashMovementDialog.tsx`: For Cash In/Out.
    *   Inputs: `type` (In/Out), `amount`, `reason`.
    *   Action: Calls `pos.cash.movement.create`.
*   `[NEW] SessionStatusBadge.tsx`: Visual indicator (Open/Closed/Suspended).

### 2. POS Pages (`packages/core/src/modules/pos/backend`)
*   `[NEW] registers/[id]/components/RegisterSessionActions.tsx`:
    *   Buttons: "Open Session", "Close Session", "Cash In/Out".
    *   State: Determines which buttons to confirm based on `register.currentSession` status.
*   `[NEW] sessions/page.tsx`: **Admin List** of all sessions (Audit Log).
    *   Columns: ID, Register, User, Status, Variance.
*   `[NEW] sessions/[id]/page.tsx`: **Admin Detail** view.
    *   Shows: Opening Float, Cash Moves List, Closing Cash, Variance.

    *   Click "Close Session".
    *   **Expect**: Field to enter cash. (Start with `130.00`).
